PRD: RG QR Video Transfer 인코더 (generate_qr_video.py)
- 네트워크 단절 폐쇄망 환경을 위한 광학 텍스트 애니메이션 QR GIF 생성 시스템

1. 개요
────────────────────────────────────────────────────────────────────────────────────────
• 제품명 : RG QR Video Transfer 인코더 (generate_qr_video.py)
• 구성 : 송신 측 인코더 파이썬 스크립트 (CLI 기반)
• 한 줄 정의 : 폐쇄망 환경에서 텍스트 파일을 쪼개어 애니메이션 QR GIF로 변환·재생하고,
             수신기(receiver.html)가 카메라로 촬영하여 원본 텍스트로 복원할 수 있게 하는 인코더.

2. 배경 및 문제 정의
────────────────────────────────────────────────────────────────────────────────────────
• 사내망 차단, 망분리, 보안 정책 등으로 두 기기 간 USB 및 네트워크 파일 전송이 불가능한 상황 존재.
• 정적 QR 코드 1개는 담을 수 있는 데이터량이 제한적(수백 바이트)이므로 긴 문서 전송 불가능.
• 텍스트를 여러 개의 최적화된 QR 조각으로 나눠 프레임 단위로 순차 재생하면,
  카메라 스캔만으로 오프라인·비접촉 전송 가능.

3. 목표 및 비목표
────────────────────────────────────────────────────────────────────────────────────────
[목표]
• 텍스트 파일(.txt, UTF-8/CP949)을 입력받아 애니메이션 GIF(QR 시퀀스)로 변환한다.
• 모바일 카메라 스캔 인식률을 최적화하기 위해 30 Byte 바이트 분할 모드와 90자 글자 수 분할 모드를 동시 지원한다.
• 별도 서버나 네트워크 연결 없이 파이썬 기본 환경(Pillow, qrcode 패키지)만으로 동작한다.

[비목표]
• 1차 버전은 바이너리 파일(이미지, 실행파일 등) 전송은 제외하고 텍스트 문서 전송에 집중한다.
• 양방향 통신(수신 확인 피드백) 없이 단방향 광학 전송만 다룬다.

4. 사용자 시나리오
────────────────────────────────────────────────────────────────────────────────────────
[송신자]
1. 터미널에서 `python generate_qr_video.py <입력.txt> [출력.gif] [프레임간격ms]` 실행
2. 생성된 GIF 파일(qr_video.gif)을 송신측 모니터/노트북 화면에 재생
[수신자]
3. 수신 기기 스마트폰 브라우저에서 receiver.html 접속 후 카메라로 화면 스캔
4. 100% 수신 완료 시 원본 텍스트 자동 복원 및 파일 저장/클립보드 복사

5. 기능 요구사항 (Functional Requirements)
────────────────────────────────────────────────────────────────────────────────────────
FR-1  입력 텍스트 파일을 UTF-8 또는 CP949 인코딩으로 자동 판별하여 읽어들인다.
FR-2  문서 맨 앞의 UTF-8 BOM 식별자(\uFEFF, ï»¿)를 원천 자동 제거(Strip)한다.
FR-3  텍스트를 조각당 CHUNK_BYTES(기본 30 Byte) 단위로 분할한다. (CLI 옵션으로 CHUNK_CHARS 90자 선택 가능)
FR-4  실행 시마다 무작위 4자리 대문자 16진수 세션 ID를 발급한다 (0000~FFFF).
FR-5  각 조각을 `RG:<세션ID>:<인덱스>:<총개수>:<내용>` 포맷으로 직렬화한다.
      (콜론 구분자 사용, 파싱 시 4번째 콜론 이후 문자열은 전체를 내용으로 취급)
FR-6  각 조각을 QR 코드로 인코딩한다 (오류정정 레벨 M, box_size=10, border=3).
FR-7  QR 이미지를 640x640px 크기로 NEAREST 보간법으로 리샘플링하여 안티앨리어싱 번짐을 방지한다.
FR-8  QR 하단에 60px 높이의 흰색 라벨 영역을 추가하고 "RG <세션ID> | <인덱스+1> / <총개수>" 텍스트를 중앙 정렬 표기한다.
FR-9  Windows(맑은 고딕), macOS(애플 고딕), Linux(나눔 고딕) OS별 한글 폰트를 자동 탐색하여 라벨을 렌더링한다.
FR-10 모든 프레임을 이어붙여 무한 반복(loop=0) 및 지정된 프레임 간격(FRAME_MS, 기본 150ms)의 최적화된 애니메이션 GIF로 저장한다.
FR-11 CLI 인자(입력 파일 필수, 출력 파일명 선택, 프레임 간격 선택, --chunk-bytes, --chunk-chars)를 제공한다.
FR-12 처리 중 10프레임마다 콘솔 터미널에 진행률(%)을 안전하게 출력한다.

6. 데이터 프로토콜 명세
────────────────────────────────────────────────────────────────────────────────────────
• 포맷 : RG:{sessionId}:{index}:{total}:{content}
• sessionId : 4자리 대문자 16진수 문자열 (예: 9B7B)
• index     : 0-based 정수 (0 <= index < total)
• total     : 1 이상의 정수 (전체 조각 수)
• content   : UTF-8 문자열 (콜론 포함 가능)
• 파싱 규칙 : 콜론(:) 기준 최대 4번만 분리(split limit=4)하여 앞 4개 필드만 추출

7. 비기능 요구사항 (Non-Functional Requirements)
────────────────────────────────────────────────────────────────────────────────────────
NFR-1 (인식 성공률) : 초당 약 6.7 FPS(프레임당 150ms) 기준 모바일 카메라 스캔 인식 성공률 100% 확보.
NFR-2 (성능)        : 100KB 텍스트 기준 인코딩 처리 시간 수 초 이내 완료.
NFR-3 (가시성)      : 20~50cm 거리에 모니터를 비추었을 때 640px 캔버스로 선명하게 인식.
NFR-4 (오프라인)    : 외부 네트워크 요청 없이 완전 오프라인 로컬 환경에서 동작.

8. 에러 처리 및 예외 케이스 (Edge Cases)
────────────────────────────────────────────────────────────────────────────────────────
EC-1 입력 파일 부재 또는 빈 파일 → 명시적 오류 메시지 출력 후 안전 종료.
EC-2 한글 폰트 미설치 → 기본 PIL 폰트로 자동 폴백(Fallback).
EC-3 Windows 터미널 cp949 인코딩 오류 → sys.stdout.reconfigure(encoding="utf-8")로 자동 회피.
EC-4 용량 과다로 인한 오버플로우 → 30 Byte 저밀도 QR 분할로 오버플로우 원천 차단.

9. 명령행 사용법 (CLI Reference)
────────────────────────────────────────────────────────────────────────────────────────
# 1. 기본 실행 (150ms 간격, 30 Byte 스캔 최적화 모드)
python generate_qr_video.py 입력문서.txt [출력파일.gif] [프레임간격ms]

# 2. 예시
python generate_qr_video.py "[PRD] QR_receiver.txt" prd_video.gif 150

# 3. 90자 단위 글자 수 분할 사용 시
python generate_qr_video.py 문서.txt output.gif 150 --chunk-chars 90
